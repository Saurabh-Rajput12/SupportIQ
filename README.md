# SupportIQ — Intelligent Support Ticket Triage and Auto-Reply Engine

> **Academic context:** MCA (Data Science) Project  
> **Mandatory Architecture:** HTML5/CSS3/Vanilla JS + Node.js/Express/SQLite + Python/FastAPI/PyTorch/Transformers  
> **Version:** 1.0.0 (Research-backed baseline)

SupportIQ is a human-supervised customer-support ticket triage and AI drafting application. It implements four syllabus experiments within an end-to-end operational triage workflow:
1. **Experiment 1:** NLP Preprocessing and Tokenization (`ml_service/app/preprocessing/`)
2. **Experiment 2:** BERT Intent Classification on BANKING77 (`ml_service/app/intent/`)
3. **Experiment 3:** T5 Conditional Summarization (`ml_service/app/summarization/`)
4. **Experiment 4:** Prompt Engineering for AI Reply Drafting (`ml_service/app/reply_generation/`)

---

## Key Architectural Principles & Non-Negotiable Boundaries

- **Human-in-the-Loop AI:** The engine produces **drafts only**. Every response must be inspected, edited, approved, or rejected by an authenticated agent. Approval persists the decision with `sent: false`. Automatic outbound message or email sending is prohibited.
- **Service Isolation:** 
  - Frontend talks strictly to Node.js/Express over REST JSON.
  - Express coordinates business workflows, validation, and writes to SQLite (`PRAGMA foreign_keys = ON;`).
  - Python FastAPI ML Service manages inference and priority logic. It has zero direct access to the database.
- **Explainable Triage Priority:** Triage urgency (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`) is generated by a transparent, versioned rule engine with explicit reason codes, NOT an opaque black-box neural classifier.
- **Honest Dataset Boundaries:** PolyAI BANKING77 (13,083 queries, 77 intents, CC-BY-4.0) provides intent labels only. DistilBERT SST-2 sentiment is strictly binary (`positive` / `negative`); low confidence surfaces as `uncertain`, not as a fictitious neutral class.

## Quickstart & Launch Guide

### Prerequisites
- Node.js LTS (v20+ recommended)
- Python 3.11+
- Git

### 1. Backend Setup & Database Migration
```bash
cd backend
npm install
npm run db:migrate
npm run db:seed
npm test
npm start
```
*Backend runs on `http://localhost:3000`.* Default seeded agent: `agent@supportiq.local` (Password: `AgentSecurePass2026!`).

### 2. Python ML Service Setup
```bash
cd ml_service
python3 -m venv .venv
source .venv/bin/activate   # On Windows: .venv\Scripts\activate
pip install -r requirements.txt
pytest tests/
uvicorn app.main:app --host 127.0.0.1 --port 8000
```
*Interactive Swagger docs available at `http://127.0.0.1:8000/docs`.*

### 3. Accessing the Frontend Dashboard
Navigate to `http://localhost:3000/` in any modern web browser.
- **Overview:** Real-time KPI summary, Chart.js ticket status & priority distributions, ML service readiness.
- **All Tickets:** Filterable, searchable ticket register.
- **Create Ticket:** Submit new ticket with optional automatic NLP analysis trigger.
- **AI Reply Review:** Inspect draft, edit response, approve (`sent: false`), reject with reason, or regenerate.
- **Model Evaluation:** Inspect syllabus experiment benchmark figures.

## API Summary

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/v1/health` | Backend health check |
| `POST` | `/api/v1/auth/login` | Authenticate agent and issue session token |
| `GET` | `/api/v1/tickets` | List tickets with filters (`status`, `priority`, `search`) |
| `POST` | `/api/v1/tickets` | Create a new ticket (status: `NEW`) |
| `GET` | `/api/v1/tickets/:id` | Retrieve ticket, latest analysis, reply, and history |
| `POST` | `/api/v1/tickets/:id/analyze` | Run full NLP pipeline via Python ML service |
| `PATCH` | `/api/v1/replies/:replyId` | Save agent edits to draft (revokes approval if previously approved) |
| `POST` | `/api/v1/replies/:replyId/approve` | Approve reply draft (`sent: false`) |
| `POST` | `/api/v1/replies/:replyId/reject` | Reject draft with mandatory audit reason |
| `POST` | `/api/v1/tickets/:id/replies/regenerate` | Generate a new version using selected prompt strategy |
| `GET` | `/api/v1/analytics/overview` | Persisted SQLite KPI metrics |
| `GET` | `/api/v1/analytics/distributions` | Chart aggregates for status, priority, and intent |

## Security & Ethics Notes
- All state-changing agent actions are audited in SQLite `ticket_history`.
- External customer input is strictly delimited as untrusted data in prompt templates to prevent prompt injection.
- Passwords are encrypted with `bcrypt` (10 rounds).
- SQL statements use parameterized queries to prevent SQL injection.
- Frontend renders user input with `textContent` / escaped templates to prevent XSS.
